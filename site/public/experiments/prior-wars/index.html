Prior Wars

Every ML Ratchet model learns only from a physics simulator. TabPFN also learned only from synthetic data, but from a generic prior over random causal models, and it predicts by reading a table in context. This experiment asks which prior does better on the collection's real exams, and how many real labels the generic prior needs to catch up.

The arms

P · physics prior

The released simulation-trained model, rerun from its shipped weights. It has seen 0 real labels.

G-dev · generic prior + k labels

TabPFN-v2 with the model's real dev rows in context. It has seen k real labels, so its protocol differs from P's.

G-sim · simulator as data

TabPFN-v2 with 1,024 simulated rows from the model's own training bank in context. It has seen 0 real labels.

G-sim+dev · both

The simulated rows plus every dev row in one context, with an is_real flag column.

What this shows, and what it does not

    Protocol

    • The protocol was pre-registered in PREREG.md before any exam row was scored. Each model's section is hashed into prereg_log.json before its exam predictions, and the scoring code refuses to run if that hash has changed. The exam is scored once and chooses nothing.
    • Settings were chosen without the exam. G-dev preprocessing (raw or normalised) came from 5-fold cross-validation inside dev. G-sim preprocessing came from 400 rows of the model's frozen simulated validation set.
    • TabPFN-v2 ran on one CPU core with n_estimators = 2, under a 2 GiB memory cap on a machine shared with two other agents. Context rows are capped at R_max(F) by feature count, and G-sim uses 1,024 rows. These limits are fixed in amendments A1-A3. The result is a lower bound on what TabPFN can do.
    • Two exams were subsampled once with a fixed seed: EnergyNet (8 trips per car) and PlantDetective (2 year-windows per unit). P is scored on the same rows.
