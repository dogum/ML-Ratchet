# Next physics + ML projects (ChirpNet-style) — updated 22 Nov 2026

> Kept as written on 22 Nov 2026 in the cloud project, with names of people and build roles made neutral and the claude.ai page links replaced by each model's `lab/` in this repository. Paths and status refer to that project.

Each project follows the same recipe:
1. Real physics.
2. Simulate lots of data (since TransitNet: inject into real instrument noise where possible).
3. Train a network.
4. Ratchet: a new version is kept only if it beats the old one on held-out simulations, and also on a small real-data dev set that no exam uses.
5. Final exam on real data that was never used for choosing.

## Brainstorm, 22 Nov 2026 (after Wildfire): the B batch, the wind tunnel, Rust/WASM

**B batch: done 22 Nov** (see each `*-status.md`). Four single models in parallel. Each fills an empty slot on the Model families page.

| Project | Family | Physics → real exam |
|---|---|---|
| QuakeNet v2 (multi-station) | Graph network | QuakeNet's simulator per station → USGS locations on QuakeNet's multi-station exam events |
| TsunamiNet | Normalizing flow (+ optional neural operator) | Okada seafloor sources + linear shallow-water propagation → real DART buoy records |
| LawFinder | Symbolic regression | Readable laws pulled out of WaterSim, FireSim, GridSim, BuildingSim and RoadSim → each tested on that platform's real exam |
| AirfoilNet ("the wind tunnel", scoped) | Operator / graph network on fields, or MLP on polars | XFOIL-class panel + boundary-layer physics → UIUC low-speed wind-tunnel polars (reachable); NeuralFoil (trained on XFOIL) as the learned rival |

Results (each exam run once):
- **QuakeNet v2:** wins on epicentre at every station count (median 127 km with all stations vs 240 for v1.2 combined classically, and 173 for a travel-time locator) and on origin time. Loses on Mw and on deep quakes.
- **TsunamiNet:** wins on Mw (0.23), centroid (45 km vs SIFT-style NNLS 82) and held-out DART amplitude (79 % within a factor of 2). Loses when every event is weighted equally. Its flow posterior is honest on thrusts, not on other mechanisms.
- **LawFinder:** five laws.
  - Fire growth law beats FireCast on growth days.
  - GB nadir law, 0.060 Hz, beats GridPulse (0.080) and the textbook (0.173).
  - Water law beats Budyko–Fu but not FlowCast.
  - Inertia and homes laws lose.
  - The RoadSim law was not built.
- **AirfoilNet:** beats NeuralFoil on Cl max and stall angle, and loses on drag, moment and Cl elsewhere. The operator family (DeepONet) was tried and rejected, so that slot is still empty.

Alternates for a later batch: GPSQuake (Gaussian processes), river digital twin (data assimilation), DiffusionNet (attention), SpinRock (sets + flow).

**The wind tunnel (the owner's question, 22 Nov).**
- "Best possible" CFD is out of reach on this machine; high-fidelity turbulence needs GPU clusters, and even it is imperfect.
- 2D airfoils are the sweet spot:
  - XFOIL-class physics runs in seconds.
  - Real tunnel data exists (Selig's UIUC low-speed airfoil tests).
  - The simulator's known weakness, stall and separation, is exactly what twin tests would expose.
- The pitch: "XFOIL vs NeuralFoil vs a ratcheted model, all graded on real tunnel data". NeuralFoil is graded against XFOIL, not against tunnels.
- Later rungs: RANS (SU2/OpenFOAM) on a small set, then 3D (DrivAerNet-class datasets) if a GPU host ever exists.

**Porting simulators to Rust → WebAssembly (the owner's idea, 22 Nov).**
- **Why:** not speed in Python (numba is already near C, so at most 1–3× faster), but running the *simulator itself* live on the site. Imagine FireSim spreading a fire across a real landscape as you drag the wind, or WaterSim routing a storm. Today the site runs only the networks.
- **How:** one Rust core with two front ends: wasm-bindgen/wasm-pack for the browser, and PyO3/maturin for Python.
- **Guardrail:** the verified Python package stays the reference. Every port must reproduce the platform's `checks/*.json`, as the site's network instruments already do with parity tests.
- **Pilot:** FireSim's minimum-travel-time spread kernel. It is small, it is where the time goes, and it is the most visual. The spec for the repository session is in `wasm-pilot-spec.md` (in this repository: `docs/wasm-pilot.md`).
- **Later:** WebGPU, only if something needs it.

## Lessons carried forward

- (22 Nov, B batch) Anchors win again. QuakeNet v2 and TsunamiNet both correct a classical answer (combined per-station readings; an NNLS inversion) rather than predict from scratch, and both beat the anchor on location.
- (22 Nov) A one-line law can beat a network. LawFinder's nadir law beat GridPulse, and its fire growth law beat FireCast on growth days. The same search also shows what each simulator wrongly believes: FireSim's fires grow about 36× too much, and GridSim's GB inertia per MW is about 35 % low.
- (22 Nov) More simulation can hurt. AirfoilNet's bigger banks raised the simulated score and lowered the real dev score. The dev gate caught it, as it did in SwellCast and StarQuake.
- (22 Nov) Fortran (XFOIL) and Julia (PySR) were both impractical on the shared box. AirfoilNet used mfoil (MIT) via PyPI; LawFinder wrote its own PySR-style search in numpy.

- (19 Nov, Wildfire) Twin tests in three models found the same gap: simulated fires grow on 91 % of half-days, real ones on 50 % (no burnout or stalls). One persistence fix would touch every fire model.
- (19 Nov) FireCast doubled the AP of the calibrated physics replay it was trained from (0.355 vs 0.165). A network trained on randomized, noisy simulations learns to hedge where a deterministic replay over-commits.
- (19 Nov) FireSize: the network reproduces its simulator at AUC 0.91, but the simulator reproduces reality at only 0.67. Measure both numbers to find out whether the network or the physics is the ceiling.
- (19 Nov, Prior Wars) k\*, the number of real labels a generic learner needs to match the physics model, works as a fidelity meter for each simulator. It is low where simulators have known human-behaviour gaps (buildings, plants) and high where physics carries the signal (vehicles).
- (19 Nov) The interface stall killed the Phase 2 builds mid-run. Resuming from STATUS.md worked again; every build checked for a started exam before resuming.

- (18 Nov, Watershed) The biggest sim-to-real gap was the *forcing data*, not the physics. ERA5-Land undercatches mountain precipitation and drifts about 6 % between decades. Twin tests in three separate models found it. Check the input product before blaming the simulator.
- (18 Nov) Learned models clearly won where the physics is local and clean (SnowSense beat every ungauged baseline) and in control problems with an exact cost (ReservoirPilot, 7× better than SOP). They tied or lost where classical methods borrow real behaviour from neighbours: ungauged streamflow regionalisation, and detecting regulation.
- (18 Nov) An NSE* loss weighted by the target's std biases simulation-trained ungauged models low, because the std depends on hidden parameters. Scale by an input-derived quantity instead.
- (18 Nov) Control models will exploit what the cost doesn't charge: ReservoirPilot holds reservoirs low because J has no storage term. Always report every component of the cost.

- (17 Nov, BuildingSim) Phase 2 builds survived a container restart by resuming from their STATUS.md files. Relaunching with "resume from your folder" worked.
- (17 Nov) Four builds share a ~6.3 GB memory limit; one bank process was killed for running out of memory. Keep bank processes small and restartable.
- (17 Nov) A recurring pattern across all three big systems: physics-trained models win where the physics is clean and lose where real systems have operator habits the simulator lacks. Examples: campus district plants, 24/7 air handlers, heat-pump controls.
- (17 Nov) Twin tests keep finding the biggest gaps. BMS logs commands, not positions. Real dampers are nonlinear. Real campus meters are flat.

- (14 Nov, GridSim) The two-phase big-system recipe worked a second time:
  - The two Phase 1 builds cross-checked each other's data. GridSim flagged a GB event label about 2× too large.
  - The Phase 2 builds filed concrete upstream fixes.
  - Watch for exam-period leakage in "defaults": GridSim cited 2024/25 reliability aggregates.
- (14 Nov) Weather/forecast archives (Open-Meteo previous runs) rate-limit the shared IP. Plan forecast-mode exams as a download from the owner's own machine.
- (14 Nov) Physics-trained models that beat operators usually win on the physics-heavy part and lose where the real data has reporting quirks:
  - DemandCast wins on demand and loses on solar (timestamp shifts).
  - PlantDetective wins on coal and steam units and loses on combined cycles (gross-load reporting).

- (13 Nov, vehicle project) For big systems problems, split the work: Phase 1 builds a shared simulator and a shared data/splits package in parallel against a written contract, then Phase 2 runs the models in parallel on top. Freeze the shared layers during Phase 2 and let each build patch in its own folder; upstream afterwards.
- (13 Nov) Builds checking each other's work catch real bugs: EnergyNet found swapped EPA cycle labels and a double-counted payload in RoadData.
- (13 Nov) When the model is a controller, the exam has to be "real routes in the simulator", plus a separate simulator-vs-real check, which showed fidelity gaps (~20%) much bigger than the gaps between strategies (1–3%).

- (6 Nov, from four parallel projects) Four parallel builds on a 2-core sandbox worked: each took 1–2 h, kept to one thread and small models, and survived 2–3 container restarts through resumable checkpoints. The shared brief was `/home/claude/AGENT_BRIEF.md` (cloud workspace, temporary; now docs/history/agent-brief-2026-11.md).
- (6 Nov) The ratchet regularly rejects "calibrated" simulators that match dev statistics better but read real dev data worse (SwellCast v2/v3, StarQuake v2, BeatNet r4). Mixing banks (old + calibrated) is the usual fix.
- (6 Nov) A small dev set can be too kind (BearingNet Paderborn dev 0.78 vs exam 0.45). Use dev units from several machines/conditions.
- (6 Nov) Always include the dumb baseline: SwellCast's median guess wins on distance/time because the exam geometry is narrow.

- Calibrate the simulator on a handful of real units, and keep them as a dev set that never enters an exam.
- Simulator realism that helps the simulated exam can hurt real data; let the dev set decide.
- Priors on rates (aging, failure) and nuisance physics (limb darkening) matter as much as the main physics; fit them on dev units.
- Inject simulated signals into real instrument noise when the instrument has public archives.
- Predict corrections to the model-free estimate instead of absolute values.
- Check every catalogue input (TransitNet: periods drift; per-sector alignment needed).
- Plot real dev records next to simulations of the same event early. In QuakeNet, the two biggest gains (slow surface waves, scattering coda) came from doing this.
- Match the simulator's source mix to the real world, using data that predates the exam (QuakeNet: the 1990–2011 catalog).
- Compare every output against a dumb baseline. QuakeNet's shallow depth loses to always guessing 31 km, and the page says so.
- Long jobs need resumable checkpoints, because the cloud container can restart.

## The collection repo and a physics MCP (the owner's idea)

  - `chirpnet.scan`
  - `sundoctor.diagnose`
  - `cellsense.health`
  - `transitnet.read`
  - `quakenet.read`
