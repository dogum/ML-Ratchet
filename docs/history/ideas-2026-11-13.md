# Next physics + ML projects (ChirpNet-style) — updated 13 Nov 2026

Each project follows the same recipe:
1. Real physics.
2. Simulate lots of data (since TransitNet: inject into real instrument noise where possible).
3. Train a network.
4. Ratchet: a new version is kept only if it beats the old one on held-out simulations, and also on a small real-data dev set that no exam uses.
5. Final exam on real data that was never used for choosing.

## Lessons carried forward

- (13 Nov, vehicle project) For big systems problems, split the work: Phase 1 builds a shared simulator and a shared data/splits package in parallel against a written contract, then Phase 2 runs the models in parallel on top. Freeze the shared layers during Phase 2 and let agents patch in their own folders; upstream afterwards.
- (13 Nov) Agents checking each other's work catch real bugs: EnergyNet found swapped EPA cycle labels and a double-counted payload in RoadData.
- (13 Nov) When the model is a controller, the exam has to be "real routes in the simulator", plus a separate simulator-vs-real check, which showed fidelity gaps (~20%) much bigger than the gaps between strategies (1–3%).

- (6 Nov, from four parallel projects) Four Opus agents in parallel on a 2-core sandbox worked: each took 1–2 h, kept to one thread and small models, and survived 2–3 container restarts through resumable checkpoints. The shared brief is `/home/claude/AGENT_BRIEF.md` (cloud workspace, temporary).
- (6 Nov) The ratchet regularly rejects "calibrated" simulators that match dev statistics better but read real dev data worse (SwellCast v2/v3, StarQuake v2, BeatNet r4). Mixing banks (old + calibrated) is the usual fix.
- (6 Nov) A small dev set can be too kind (BearingNet Paderborn dev 0.78 vs exam 0.45). Use dev units from several machines/conditions.
- (6 Nov) Always include the dumb baseline: SwellCast's median guess wins on distance/time because the exam geometry is narrow.

- Calibrate the simulator on a handful of real units, and keep them as a dev set that never enters an exam.
- Simulator realism that helps the simulated exam can hurt real data; let the dev set decide.
- Priors on rates (aging, failure) and nuisance physics (limb darkening) matter as much as the main physics; fit them on dev units.
- Inject simulated signals into real instrument noise when the instrument has public archives.
- Predict corrections to the model-free estimate instead of absolute values.
- Check every catalogue input (TransitNet: periods drift; per-sector alignment needed).
- Plot real dev records next to simulations of the same event early. In QuakeNet, the two biggest gains (slow surface waves, scattering coda) came from doing this.
- Match the simulator's source mix to the real world, using data that predates the exam (QuakeNet: the 1990–2011 catalog).
- Compare every output against a dumb baseline. QuakeNet's shallow depth loses to always guessing 31 km, and the page says so.
- Long jobs need resumable checkpoints, because the cloud container can restart.
